# 08 — Finn-loop: چه چیزی گرفتیم، چه چیزی نگرفتیم و چرا

> منبع: github.com/finna/Finn-loop (MIT، ۳۰۵⭐) — سه اسکیل Claude Code: `finn-spec` (مصاحبه → issue با AC/NG)، `finn-build` (یک issue → یک PR)، `finn-review` (بازبین تازه → verdict سه‌گروهی). قانون اصلی آن: **انسان merge می‌کند**.

## مقایسه با لوپ ما

| موضوع | Finn-loop | لوپ ما (قبل) | تصمیم |
|-------|-----------|--------------|-------|
| قرارداد کار | issue با `AC-N` (معیار پذیرش مشاهده‌پذیر) + `NG-N` (نا-هدف‌های الزام‌آور) | کارت با goal / real_test / done_when؛ بدون نا-هدف صریح | **گرفتیم** → هر مرحله قبل از کد یک `CONTRACT.md` با AC/NG می‌نویسد |
| بازبینی | بازبین **تازه با کانتکست خالی**، نه سازنده؛ verdict با تگ `[AC-N]` `[DEFECT]` `[SECURITY]` `[CI]` `[SCOPE-CONFLICT]` | خودِ سازنده تست را می‌دواند و GREEN می‌زند | **گرفتیم** → گام جدید ⑧ REVIEW با سشن/ایجنت جدا و وضعیت `REVIEW` در دفترچه |
| سقف تکرار | ۲ دور fix ناموفق → `loop-stuck` → انسان | ۵ تکرار debug → BLOCKED | **ترکیب**: ۵ تکرار سازنده + حداکثر ۲ دور بازبینی؛ بعد `BLOCKED` |
| Scope ledger | در PR: یک خط شواهد برای هر AC، یک خط «حفظ شد» برای هر NG، `Other behavior changes: None` | پیام commit آزاد | **گرفتیم** → قالب commit/PR اجباری |
| مسدود شدن | فقط **یک سؤال مشخص با گزینه‌ها** که به‌صورت async قابل پاسخ است؛ «مبهم است» ممنوع | U3 با پیش‌فرض | **گرفتیم + بهتر**: سؤال با گزینه‌ها **و** پیش‌فرضِ اعمال‌شده در سکوت |
| CI غایب | «CI غایب = سبز نیست» → escalate | Skip ≠ Pass | همسو بود؛ صریح‌تر شد |
| Preflight | working tree تمیز، تشخیص default branch، یک واحد کار در هر pass | Sync | **گرفتیم** → `git status --porcelain` باید خالی باشد |
| Watchdog | stall خاموش / CI قرمز / صف ناسالم → هشدار | — | **گرفتیم** (سبک) → `verify_ledger` هشدار برای AMBER > 72h و RED با iter ≥ 3 |
| انسان merge می‌کند | هر PR | — | **نگرفتیم** — با «کمترین دخالت» شما در تضاد است. دروازه‌ی انسانی ما فقط **مایلستون** (U2) است |
| Linear + Slack | منبع حقیقت و کنترل‌پلن | `steps.json` + `04_LEDGER.md` در ریپو | **نگرفتیم** — ریپو خودش منبع حقیقت است؛ وابستگی خارجی اضافه نمی‌کنیم |
| `/loop` Claude Code | اجرای تکراری اسکیل | لوپ ۹ گامی دستی‌/ایجنتی | **نگرفتیم** به‌عنوان وابستگی؛ ولی پروتکل ما طوری است که در هر ایجنتی (`/loop`، cron، سشن Arena) اجرا شود |

## آنچه عملاً تغییر کرد
1. `02_LOOP_PROTOCOL.md` — گام ⑧ به **REVIEW (بازبین تازه)** تبدیل شد؛ Evidence به ⑨ و Commit به ⑩ رفت. قالب verdict و scope ledger اضافه شد.
2. `04_LEDGER.md` — وضعیت جدید `REVIEW` (کد کامل، تست سازنده سبز، منتظر verdict بازبین). `verify_ledger.py` آن را می‌پذیرد و GREEN بدون فایل `REVIEW.md` را رد می‌کند.
3. `docs/loop/templates/CONTRACT.md` و `REVIEW.md` — قالب‌های اجباری برای هر مرحله در `docs/loop/evidence/S-xxx/`.
4. `07_SESSION_HANDOFF.md` — دو نقش جدا: **Builder** و **Reviewer** (هرگز یک سشن هر دو نباشد).
