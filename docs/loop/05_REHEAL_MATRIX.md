# 05 — Reheal Matrix (۷ لایه × مراحل × probeهای آشوب)

> «Reheal» فقط زمانی واقعی است که هر لایه یک **probe آشوب** داشته باشد که در CI اجرا می‌شود و بازیابی را assert می‌کند. این ماتریس مشخص می‌کند هر لایه در کدام مرحله ساخته، در کدام مرحله probe و در کدام مرحله در UI دیده می‌شود.

| لایه | نام | وضعیت فعلی (ممیزی) | مرحله‌ی ساخت | probe آشوب (S-077) | نمود در UI | معیار بازیابی |
|------|-----|--------------------|--------------|--------------------|------------|----------------|
| L1 | Memory Guard | LRU + `gc.collect` ۴۰ خط، به هیچ اندپوینتی وصل نیست | S-012 (پایه), S-075 | تزریق فشار RAM با env flag / تخصیص ۱GB مصنوعی | نوار وضعیت RAM + toast «حافظه آزاد شد» | job ادامه می‌یابد؛ RSS بعد از cleanup ≥ ۲۰٪ کمتر؛ لاگ JSON `fix=memory` |
| L2 | GPU Guard | فقط خواندن VRAM در `/health` | S-036 (float16/CPU fallback), S-075 (downscale) | mock VRAM=3600MB؛ حذف CUDA از env | badge «حالت کم‌مصرف» + پیش‌نمایش 540p | پردازش با CPU/float16 تمام می‌شود؛ خروجی هش‌برابر با حالت GPU (در حد تلرانس) |
| L3 | Pipeline Guard | validator ۳۰ خطی، استفاده‌نشده | S-006 (helpers), S-037, S-028 | فایل ۰ بایت، هدر خراب، فریم سیاه وسط ویدیو | پیام فارسی «فایل خراب است» با گزینه‌ی انتخاب دوباره | 4xx ساختاریافته، بدون 500، بدون فایل موقت باقی‌مانده |
| L4 | AI Guard | یک `try/except` با timeout 15s، بدون retry/fallback | S-053, S-056 | provider mock: 500×2 سپس 200؛ همه‌ی providerها down؛ کلید غلط؛ timeout | banner آفلاین + پاسخ قاعده‌محور محلی | ۳ تلاش با backoff؛ پاسخ محلی فارسی؛ هیچ exception به UI |

| L7 | Render Guard | وجود ندارد | S-036 (checkpoint هر ۱۰۰ فریم), S-072 (resume), S-076 (watchdog) | kill پایتون در ۵۰٪ export/enhance؛ kill ffmpeg | پیشرفت «ادامه از فریم N»؛ banner اتصال مجدد | خروجی نهایی هش‌برابر با اجرای بدون وقفه؛ sidecar در < 5s برمی‌گردد |

## قواعد ثابت برای همه‌ی لایه‌ها
1. هر رویداد Reheal یک خط لاگ JSON با فیلدهای `{ts, layer, component, event, action, ok, duration_ms}` می‌نویسد (S-073).
2. هر رویداد به `rehealStore` فرانت می‌رسد (WS از S-029) و در RehealDrawer با زمان و نتیجه دیده می‌شود.
3. هیچ لایه‌ای «خاموش» شکست نمی‌خورد: اگر بازیابی ناموفق بود، خطای صریح با راهنما به کاربر می‌رسد.
4. هر لایه در `tests/chaos/` حداقل یک تست دارد که در CI اجرا می‌شود (ubuntu برای بک‌اند، windows برای دسکتاپ).
5. تست دودی کاربر (`smoke-gpu.ps1`) L2 و L7 را روی سخت‌افزار واقعی probe می‌کند (kill پایتون + بررسی VRAM).

## بودجه‌های عددی که Reheal آن‌ها را نگه می‌دارد
| منبع | آستانه‌ی هشدار | آستانه‌ی اقدام | اقدام |
|------|----------------|----------------|-------|
| RAM اپ (همه‌ی پروسه‌ها) | 1.2 GB | 1.5 GB | cleanup → کاهش کش فریم → توقف job جدید |
| VRAM مدل‌ها | 600 MB | 800 MB | float16 → آزادسازی مدل بیکار → CPU |
| VRAM کل GPU | 3000 MB | 3500 MB | پیش‌نمایش 540p → توقف پردازش GPU |
| فضای دیسک آزاد | 2 GB | تخمین خروجی ×1.5 | رد کردن export با پیام |
| temp | — | فایل > 1h یا > 5GB کل | حذف (به‌جز فایل‌های job فعال) |
| sidecar health | ۱ شکست | ۳ شکست متوالی | restart با backoff (حداکثر ۵) |
